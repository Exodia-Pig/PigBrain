# Gradle 빌드 최적화 일반론

사내 안드로이드 프로젝트의 재빌드 시간을 평균 93%(최대 94.4%) 줄인 과정을 일반화한 방법론입니다.

**소개 및 안내**

이 글의 사례는 실제 운영 중인 안드로이드 프로젝트에서 진행한 빌드 최적화 작업을 바탕으로 합니다. 프로젝트를 특정하지 않기 위해 다음과 같이 표기합니다.

- 사내 프로젝트 → **프로젝트 G**
- 광고 미디에이션 SDK → **광고 SDK A** (관련 태스크명·플러그인 좌표는 가명으로 재구성)

본문의 재현 실험과 프로파일 리포트 캡처는 개인 사이드 프로젝트인 [ziine-android](https://github.com/Nexters/ziine-android)에서 수행하여, 누구나 같은 방법으로 검증할 수 있습니다.

## 들어가며 — 빌드 시간은 곧 개발 생산성이다

안드로이드 개발자는 하루에도 수십 번 빌드 버튼을 누릅니다. 한 번의 빌드에 2분이 걸린다면, 하루 30회 빌드 기준으로 매일 1시간을 기다림에 쓰는 셈입니다. 더 큰 문제는 이 대기 시간이 집중의 흐름(flow)을 끊는다는 것입니다.

프로젝트 G도 같은 문제를 겪고 있었습니다. 코드 한 줄을 바꾸고 다시 빌드하는 데 **2분 11초**. "원래 오래 걸리는 프로젝트"라는 체념이 팀에 퍼져 있었습니다.

그런데 정말 원래 그런 걸까요? 이 글은 그 질문에서 시작해, **어떤 Gradle 프로젝트에도 적용할 수 있는 빌드 최적화 방법론**을 정리한 것입니다. 핵심은 단순합니다.

1. **측정한다** — 어떤 태스크(Task)가 실제로 실행되고, 얼마나 걸리는지
2. **의심한다** — 그 태스크가 정말 필요한 작업인지
3. **제거한다** — 필요 없다면, 근거를 확보하고 걷어낸다
